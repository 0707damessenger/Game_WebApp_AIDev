# 桌宠应用程序 — 设计文档

## 1. 项目概述

### 1.1 核心目的

以精简、轻量、低门槛为特色的桌面宠物软件。

### 1.2 目标平台

桌面客户端（基于 Electron 框架，Web 技术栈渲染）。

### 1.3 目标用户画像

追求个性化桌面装饰的用户，包括二次元爱好者、桌面美化玩家、轻度养成类玩家。

---

```
  制作/获取桌宠
       ↓
   桌面展示互动

       ↓
  创意工坊分享 ←→ 发现新模组
```

## 3. 模块拆分

### 3.1 模块 A：制作桌宠（角色与骨骼动画系统）

#### 3.1.1 角色管理

- 支持创建、编辑、删除、复制角色
- 每个角色拥有独立的名称、缩略图
- 每个角色可绑定多套动作模组

#### 3.1.2 动作模组

动作模组是一组骨骼动画的集合，定义角色可以执行的所有动作。每个模组包含：

- **骨骼定义**：预设骨骼模板（关节名称、层级关系、初始姿态）
- **动作列表**：该模组包含的动作集合（如待机、行走、跳跃、躺下等）
- **每个动作**：定义关键帧序列，每帧记录各骨骼关节的位移/旋转/缩放

#### 3.1.3 骨骼绑定流程

骨骼绑定提供两条路径：

- **基础绑定**：导入单张 PNG，将整张图作为单一网格绑定骨骼。效果受限，适合快速预览和简单角色。
- **进阶绑定**：导入含图层的工程文件，按图层拆分部件各自绑定骨骼。达到类 Spine 的部件级骨骼动画效果。

##### 基础绑定（单张 PNG，快捷开始）

单张 PNG 绑定本质是对整张光栅图做全局网格变形，受限于图像无分部件信息：
- 关节运动时图像拉伸/压缩/撕裂，变形可控性低
- 无法实现身体部件间的遮挡关系（如手无法绕到身体后方）
- 仅适合：微弱摇晃/呼吸效果、简单 blob 类角色、快速原型预览

流程：

1. 创建角色
2. 选择动作模组
3. 导入单张 PNG 图片
4. 在图片上绑定骨骼关键点（一键预估 → 手动微调）
5. 预览动画效果
6. 保存角色配置

##### 进阶绑定（工程文件图层拆分，类 Spine 品质）

支持导入 `.psd`（Photoshop）、`.sai`（PaintTool SAI）等带图层的工程文件。系统按图层自动拆分角色为独立部件，每个部件作为独立网格绑定到对应骨骼。

流程：

1. 创建角色
2. 选择动作模组
3. 导入含图层的工程文件（`.psd` / `.sai`）
4. 图层部件拆分：
   - 系统读取各图层，生成部件列表（名称取自图层名）
   - 用户对部件列表进行合并/拆分/重命名（如合并"左上臂""左下臂"为"左臂"）
   - 支持部件排序（定义遮挡层级：上层在前、下层在后）
5. 部件绑定骨骼：
   - 用户将每个部件拖拽绑定到对应骨骼关节
   - 系统根据部件位置自动推荐绑定目标（如"head"图层自动推荐绑定到头骨）
   - 提供实时预览：各部件随骨骼联动
6. 微调各部件与骨骼的相对位置、旋转锚点
7. 预览各动作动画效果
8. 保存角色配置（含部件拆分方案 + 骨骼绑定关系 + 动画数据）

##### 两种绑定方式的对比

| 维度 | 基础绑定（单张 PNG） | 进阶绑定（图层拆分） |
|---|---|---|
| 动画品质 | 低，变形失真明显 | 高，部件独立变形自然 |
| 遮挡关系 | 不支持 | 支持（图层排序） |
| 运动范围 | 受限 | 大范围自然运动 |
| 上手难度 | 低，几分钟可完成 | 中，需要理解图层与部件关系 |
| 适用场景 | 快速原型、简单 blob 角色 | 正式角色制作 |

#### 3.1.4 骨骼动画技术规格

- **骨骼类型**：2D 骨骼动画
  - 基础绑定：基于单张图的全局网格变形（效果有限）
  - 进阶绑定：基于独立部件的多网格绑定（类 Spine 方案）
- **图片资源**：
  - 基础绑定：单张 PNG 角色图片，透明通道
  - 进阶绑定：含图层的工程文件（`.psd` / `.sai`），按图层拆分为独立部件，每个部件为独立 PNG 网格
- **骨骼模板**：系统预置若干通用骨骼模板（人形、兽形、球形等）
- **部件系统（进阶绑定专用）**：
  - 每个部件 = 一个图层导出的独立图像
  - 部件独立绑定到对应骨骼关节
  - 部件排序控制遮挡层级（z-order）
  - 每个部件可独立设置旋转锚点
- **动画引擎**：自实现 Canvas 2D 骨骼系统（骨骼变换 + 图像网格变形），不依赖外部骨骼库

### 3.2 模块 B：使用桌宠

#### 3.2.1 常规使用

##### 悬浮窗

- 无边框、置顶（always-on-top）、半透明通道渲染
- 可拖拽移动至屏幕任意位置
- 支持多实例（同时展示多个桌宠）
- 窗口尺寸随角色缩放自适应

##### 交互方式

- **拖拽移动**：鼠标按住桌宠拖拽到屏幕任意位置
- **点击交互**：鼠标点击桌宠触发响应（抚摸动画、音效反馈、状态变化等）
- **右键菜单**：弹出上下文菜单，包含：切换动作模组、切换角色、隐藏桌宠、打开设置、退出程序
- **悬停反应**：鼠标悬停时显示气泡提示（心情文字、表情符号、简易对话等）
- **自主行为**：在无用户交互时，桌宠自主执行随机动作（走动、跳跃、坐下、睡觉等）

##### 行为系统

- 基于状态机的自动行为切换
- 状态类型：待机、行走、空闲动作、睡眠、互动响应
- 触发条件：定时器、随机概率、用户交互事件
- 每个状态对应一组动作动画

##### 多角色管理

- 角色列表面板：查看所有已创建角色
- 支持同时启动多个桌宠实例
- 每个实例独立运行状态机

##### 联机模式（远期实现）

- 多人同时在线时，桌宠之间可见
- 桌宠可互相拜访、互动

> 功能方向已锁定；联机架构、同步范围等机制细节尚未收敛，待探索条目见 [exploration.md](exploration.md)，收敛后再迁回本节。

#### 3.2.2 AI 对话模式

##### API 配置

- 支持配置 OpenAI 兼容接口（API 地址、API Key、模型名称）
- 每个角色可绑定独立的 Prompt 设定（角色名称、性格、说话风格、背景故事等）
- API Key 本地加密存储

##### 对话交互

- 点击桌宠可弹出对话气泡/对话面板
- 用户输入文字后，桌宠根据 Prompt 设定 + AI 模型生成回复
- 回复以气泡形式展示在桌宠上方
- 支持多轮对话上下文记忆

##### 多宠对话

- 多桌宠同时启动时，可互相触发对话
- 触发方式：定时自动触发或用户手动触发
- 每次对话在两个桌宠的角色设定下展开
- 用户可通过设置开关控制是否启用此功能

### 3.3 模块 C：收集和养成

#### 3.3.1 好感度/亲密度

- 每个角色拥有好感度数值，初始为零
- 玩家通过交互提升好感度：点击抚摸、日常对话、陪伴在线（挂机）等
- 好感度达到阈值后触发阶段变化：解锁新的对话内容、新的自主行为、视觉特效（如好感度满时的特殊表情/动画）
- 好感度直接影响 AI 对话模式中角色的语气和回应倾向

#### 3.3.2 陪伴时长

- 系统记录每个角色的累计展示时长（挂机/在线总时长）
- 陪伴时长达到里程碑后解锁奖励：称号、特殊动作、边框装饰等
- 陪伴时长为纯挂机积累，无惩罚机制

#### 3.3.3 Steam 成就

- 通过 Steamworks API 接入 Steam 成就系统
- 成就触发条件示例：累计陪伴 N 小时、与某角色好感度满级、创建首个自定义角色、下载首个工坊模组等
- 成就在游戏内和 Steam 客户端同步显示

### 3.4 模块 D：创意工坊

#### 3.4.1 承载形式

- 对接 Steam 创意工坊（Steam Workshop）
- 用户通过 Steam 客户端或应用内入口浏览、订阅、发布工坊内容

#### 3.4.2 分享内容类型

- **动作模组**：玩家自制的骨骼动画模组（骨骼定义 + 动作序列），其他玩家下载后可绑定到自己的角色
- **角色**：完整的角色配置（PNG + 骨骼绑定 + 模组关联），一键导入
- **AI 角色设定**：Prompt 配置方案（角色名称、性格、说话风格等），可供其他玩家一键应用到自己的角色

#### 3.4.3 工坊机制

- 发布流程：用户在应用内导出内容 → 通过 Steam 工坊上传 → 填写描述/标签/预览图
- 订阅机制：通过 Steam 工坊订阅 → 内容自动下载到本地 → 应用内导入使用
- 依赖管理：角色引用模组时记录依赖关系，订阅角色时提示所需模组

- **模组数据**：骨骼模板定义、动作序列、关键帧数据

### 5.1 桌面框架

- Electron：主进程管理窗口、托盘、系统事件

### 5.2 动画渲染

- HTML5 Canvas 2D
- 骨骼动画引擎：自实现（骨骼变换 + 图像网格变形），原型阶段已验证可行
