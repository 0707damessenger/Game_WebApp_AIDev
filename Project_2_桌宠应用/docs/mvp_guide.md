> 本文档为 MVP 阶段开发提供实操指引，是 [design.md](design.md) 的补充。写完即弃，不维护变更记录。

## 1. MVP 目标

在浏览器中交付一个**可运行的桌宠网页原型**，验证核心循环：

```
加载角色 → 骨骼动画播放 → 用户交互响应 → 自主行为切换
```

---

## 2. MVP 范围清单

### ✅ 范围内

| 模块 | 内容 | 验证标准 |
|---|---|---|
| 悬浮窗 | 无边框 Canvas 渲染区域，页面内可拖拽 | 能看到宠、能拖动 |
| 角色渲染 | 单张 PNG + 预置骨骼模板 + 骨骼变形动画 | 能看到角色动起来 |
| 动作播放 | 预设 3~5 个动作（待机/行走/空闲/睡觉/点击反应） | 动作连贯不跳帧 |
| 交互：拖拽 | 鼠标按住拖动角色到页面任意位置 | 拖拽流畅不卡顿 |
| 交互：点击 | 点击触发反应动作 + 气泡文字 | 点击有反馈 |
| 交互：右键菜单 | 右键弹出菜单（切换动作、隐藏、设置入口） | 菜单正常弹出与收起 |
| 交互：悬停 | 鼠标悬停显示简易气泡 | 气泡跟随鼠标位置 |
| 自主行为 | 无操作时随机行走、切换待机动作 | 有"活着"的感觉 |
| 行为调度 | 简单硬编码调度（定时器 + 随机数），非通用状态机 | 行为切换自然 |
| 配置系统 | HTML 内 JS `CONFIG` 对象管理参数 | 改数值刷新即生效 |
| 资源占位 | 纯色几何图形代替角色 PNG | 不依赖外部美术 |

### ❌ 排除（留待后续迭代）

- 自定义骨骼编辑器（使用硬编码预置骨骼）
- 多角色切换
- 多宠实例
- AI 对话模式
- 通用状态机框架
- 用户设置面板
- 数据持久化/导入导出
- 收集养成
- 创意工坊
- Electron 桌面打包

## 3. MVP 开发阶段

### 阶段 1：静态渲染

**目标**：把一张占位图形画到 Canvas 上。

- 搭建基础 HTML 页面（全屏 Canvas）
- 用绘图 API 画一个简单几何角色（圆形身体 + 四肢线条）
- 角色渲染在页面中央

**验证**：刷新浏览器能看到角色。

### 阶段 2：骨骼动画

**目标**：角色能动起来。

- 定义预置骨骼模板（简单人形：头、身体、左/右手、左/右腿共 7 个关节点）
- 实现骨骼驱动渲染：根据关节坐标旋转/缩放绘制几何形状
- 定义预设动作（至少待机、行走）的关键帧数据
- 实现关键帧插值播放

**验证**：能看到角色播放待机动画和行走动画。

### 阶段 3：拖拽交互

**目标**：能拖动角色。

- 监听鼠标事件（mousedown / mousemove / mouseup）
- 实现拖拽逻辑：按下检测碰撞 → 移动更新坐标 → 释放停止
- 行走动画与拖拽联动（拖拽时播放行走、释放后归位待机）

**验证**：按住角色能拖动到页面任意位置，松开后停在原位。

### 阶段 4：点击与悬停

**目标**：点击和悬停有反馈。

- 点击检测（区分点击与拖拽：位移小于阈值算点击）
- 点击触发反应动作（短动画）+ 气泡文字
- 悬停检测 + 气泡显示

**验证**：点击角色有动画和文字反馈；悬停显示气泡。

### 阶段 5：自主行为

**目标**：不操作时角色自己动。

- 定时器 + 随机数驱动行为选择
- 实现自主行为：随机走动（移动到随机位置）、随机空闲动作、模拟休息
- 与用户交互的优先级处理（交互中暂停自主行为）

**验证**：放置不理角色 30 秒，能看到角色自行走动和做动作。

### 阶段 6：右键菜单

**目标**：右键弹出操作菜单。

- 自定义右键菜单 DOM 元素
- 菜单项：切换动作、隐藏/显示、打开设置（占位）
- 点击菜单外部关闭

**验证**：右键点击角色弹出菜单，选择项可响应。

## 4. MVP 技术决策

### 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 渲染 | HTML5 Canvas 2D | 简单直接，几何图形绘图 API 足够 |
| 骨骼引擎 | 自实现最小骨骼系统 | MVP 阶段骨骼数量少，自实现可控 |
| 动画插值 | 线性插值 | 最简单，MVP 够用 |
| 配置 | JS 顶层 `CONFIG` 对象 | 按 workspace 规范，改值刷新即生效 |
| 状态管理 | 全局变量 + 事件驱动 | MVP 复杂度低，不需要框架 |

### 文件结构（prototype/）

```
prototype/
├── index.html          # 主页面
├── js/
│   ├── config.js       # CONFIG 配置对象
│   ├── skeleton.js     # 骨骼定义与渲染
│   ├── animation.js    # 动画帧数据与插值播放
│   ├── input.js        # 鼠标交互（拖拽/点击/悬停/右键）
│   ├── behavior.js     # 自主行为调度
│   └── main.js         # 入口：初始化与主循环
└── css/
    └── style.css       # 右键菜单/气泡样式
```

### 骨骼模板示例（MVP 人形）

```
关节层级：
  root (髋部中心)
  ├── spine (脊椎)
  │   ├── head (头)
  │   ├── arm_L (左肩 → 左肘 → 左手)
  │   └── arm_R (右肩 → 右肘 → 右手)
  ├── leg_L (左胯 → 左膝 → 左脚)
  └── leg_R (右胯 → 右膝 → 右脚)
```

### 动作数据格式

```javascript
// config.js 中定义
CONFIG.animations = {
  idle: {
    loop: true,
    duration: 2000, // ms
    keyframes: [
      { t: 0,    bones: { arm_L: { rot: 0 }, arm_R: { rot: 0 } } },
      { t: 1000, bones: { arm_L: { rot: 5 }, arm_R: { rot: -5 } } },
      { t: 2000, bones: { arm_L: { rot: 0 }, arm_R: { rot: 0 } } },
    ]
  },
  walk: { ... },
  // ...
};
```

## 5. 开发约定

- 每个阶段独立提交验证，不跨阶段混改
- 阶段内遇到问题立即修复，不带着 bug 进入下一阶段
- 每完成一个阶段，在浏览器中实际运行验证
- 所有可调参数放在 `config.js` 的 `CONFIG` 对象中
- 使用纯色几何图形占位，不引入外部图片资源
