# Record_Idea 技能说明

## 何时使用：
**AI 应主动（无需用户指令）调用的情况：**
- 讨论中出现有趣的延伸方向，但当前主线讨论不宜深入
- 用户使用弱确认语气提出想法：「可以考虑」、「也许」、「或者也行」
- AI 自身联想到了有价值但偏离主线的扩展想法
- 某个方案被否决了，但其中有一个小点还值得保留

**AI 应询问用户后决定是否调用的情况：**
- 讨论进入收尾，有模糊想法未被明确处置

> **注意**：`Record_Idea` 用于「有价值，未来也许会用」的想法。如果想法已被明确否决，请改用 `Archive_Idea` 技能。

## 操作步骤：
1. **生成想法文档**：在 `docs/ideas/` 目录下创建 Markdown 文件。
   - 文件命名格式：`idea_[关键词].md`（例：`idea_energy_recharge_button.md`）
   - 如果同一主题已有文件，在该文件末尾追加新条目，而不是新建文件。
   - 创意记录属于 `docs/` 下的补充子文档，不得替代 `docs/design.md`
2. **文档结构（极简）**：
   ```
   ## [想法名称] - [YYYY-MM-DD]
   **背景**：（一句话说明当时在讨论什么）
   **想法内容**：（具体是什么）
   **潜在价值**：（为什么值得记）
   **后续状态**：（待评估 / 已采纳 / 已归档）
   ```
3. **不打断主线**：记录完成后，AI 用一句话向用户确认「已记录想法 [名称] 到创意池」，然后继续主线讨论。
4. **主契约回写规则**：如果该想法后续被采纳为正式设计结论，必须同步更新 `docs/design.md`，并补充对应想法文档的引用关系与结论摘要。
5. **输出要求**：整个文档**必须使用简体中文**编写。

## 完成自检

- [ ] 文件已创建/追加到 `docs/ideas/idea_[关键词].md`（若同主题文件已存在则追加）
- [ ] 文档包含四个字段：背景 / 想法内容 / 潜在价值 / 后续状态
- [ ] 文档使用简体中文
- [ ] 已向用户一句话确认「已记录想法 [名称] 到创意池」
- [ ] 若想法已转化为正式设计结论，已同步回写 `docs/design.md` 并补充引用关系
