# 观鸟路线记录 · 设计文档

> 本文档是开发契约。后续开发以此为准；设计变更必须先改本文档再改原型。
> 内容只描述设计层面（玩法、规则、玩法循环、模块拆分、UI 布局、交互逻辑），不含实现细节与精准数值。

## 1. 项目概述

一站式记录观鸟路线的应用：用户边走边记录行进路线，在路线途经点记录所见鸟种，结束后生成路线图并查看本次记录。解决现有工具「记录鸟种」与「记录路线」彼此割裂的问题。

- **目标平台**：手机端（竖屏、触摸操作）。按手机真机使用逻辑设计；开发期可用浏览器手机视口验证功能闭环，最终手感以手机真机为准。
- **当前阶段范围**：仅实现「核心记录闭环」。账号、个人数据、分享导入等均为后续模块（见第 7 节）。

## 2. 核心玩法与玩法循环

核心循环（单次记录）：

```
开始记录 → 选择起点 → 行进（持续记录轨迹）
        → 途经点添加鸟种（可多次）
        → 结束 → 生成路线图 → 查看本次记录
```

状态机：

- **未开始**：主界面，等待开始记录。
- **选起点**：打开地图、定位当前点为起点，确认后进入记录中；返回则回到未开始。
- **记录中**：持续记录行进轨迹，可多次添加鸟种。
- **已结束**：生成并展示「本次记录」（路线图 + 鸟种清单）。
- **中止**：放弃本次记录，不生成任何记录，回到未开始。

## 3. 规则与交互逻辑

### 3.1 开始记录与选择起点

- 点击「开始记录」后打开地图，自动定位当前位置作为起点。
- 确认起点后进入「记录中」；选择返回则回到主界面、不开始。

### 3.2 行进与轨迹

- 进入「记录中」后，应用持续记录用户的行进路线，结束时据此生成路线图。
- 定位来源可在配置中切换：
  - **真实 GPS**：真机使用时采集真实定位。
  - **模拟行走**：开发验证期使用，在地图上以最简操作产生行进轨迹。
  - 两种来源向上层提供一致的位置数据，业务逻辑不区分来源。

### 3.3 添加鸟种

- 记录中可随时添加鸟种，该条记录**自动关联当前所在位置**，落点位于路线上。
- 单条鸟种记录包含：
  - **鸟种**：按名称搜索匹配真实鸟类名录后选定。
  - **数量**：步进增减。
  - **备注**：预设标签（可多选）+ 自定义文本。初版预设标签为：成鸟、亚成、雌、雄、飞行。
- 已添加的鸟种落点可被再次点选，点选后进入预览；用户可继续编辑鸟种、数量、备注，或删除该条落点记录。
- 当多个鸟种落点距离极近、难以单独点选时，界面应将这些落点合并为一个可点选的组合点；点选组合点后先展示其中包含的记录，再选择具体记录进行编辑。
- 鸟种落点支持显示模式开关：默认只显示落点标记；打开后在路线上显示鸟种名，便于核对记录。
- **模糊匹配**（当无法确认鸟种时按特征匹配）为低优先功能，当前阶段不实现，入口先以不可用状态占位（见第 7 节）。

### 3.4 结束与中止

- **结束**：生成路线图并进入「本次记录」页；本次记录存于本地。
- **中止**：放弃并丢弃本次记录，不生成历史。
- 结束入口位于记录主界面右上角；点击后弹出确认，提供三种选择：保存并结束 / 中止并丢弃 / 继续记录。中止为危险操作，需经此确认、避免误触。

## 4. UI 布局

整体为手机竖屏。地图作为记录场景的主背景，当前阶段直接采用真实地图瓦片，不使用几何假地图。地图瓦片与鸟类名录属于核心数据源；除这两类核心数据源外，原型阶段不引入美术资源，界面图形与标记使用纯色几何占位。

### 4.1 记录主界面（记录中）

- 地图全屏铺底，行进轨迹叠加其上。
- **头顶**：状态胶囊，显示本次时长、距离、已记录鸟种数。
- **底部**：仅一个「添加鸟种」大按钮（主操作，拇指可达）。
- **右上角**：「结束」按钮（角落不易误触、又一步可达），点击弹出结束确认。
- **地图工具**：提供缩放控件；提供鸟种名显示开关，用于在落点标记与落点名称之间切换。

### 4.2 添加鸟种弹层

从底部弹出，覆盖在地图上：

- 鸟种名称搜索框，结果列表展示匹配的中文名（附学名）。
- 数量步进器。
- 备注：预设标签多选 + 自定义文本输入。
- 「添加到当前位置」确认；提示本条将记录在当前所在位置。
- 底部一条不可用的「模糊匹配」入口占位。

### 4.3 本次记录页（结束后）

- **顶部概要**：日期 / 地点、时长、距离、鸟种数与总只数。
- **中部路线图**：完整轨迹 + 各鸟种落点，点击落点可定位。
- **鸟种清单**：本次所有鸟种记录（名称、备注、数量），点击条目高亮对应落点；与记录主界面的落点预览/编辑逻辑保持一致。
- **底部**：返回主界面。分享为后续模块，此处以不可用状态占位。

## 5. 逻辑模块拆分（设计层）

- **定位源**：提供真实 GPS 与模拟行走两种来源，对上层暴露一致的位置数据；来源由配置切换。
- **地图与轨迹**：真实瓦片底图 + 行进轨迹的绘制与更新。
- **鸟种记录**：名录搜索、数量、备注、与当前位置关联，组成单条鸟种记录。
- **记录数据模型**：一次记录 = 行进轨迹 + 一组带位置的鸟种记录 + 概要信息。
- **结果呈现**：由记录数据生成路线图与鸟种清单。
- **配置**：全项目唯一配置源，集中承载所有数值与功能开关（含定位来源、地图底图等）。

## 6. 数据与资源策略

- **记录持久化**：本次记录在结束后保存到本地，保证结束后可查看。完整的历史列表与增删改属后续模块。
- **鸟种名录**：直接采用真实中文鸟类名录作为搜索数据来源，原型阶段先以本地可用名录起步。
- **地图底图**：直接采用真实地图瓦片。初期使用免费公共瓦片源以便零配置起步；后续需支持国内可稳定访问的瓦片源，切换时需处理坐标系差异（国外源与国内源坐标体系不同，定位与落点需做相应纠偏）。
- **占位资源**：地图瓦片与鸟类名录不做占位；其他界面图形、按钮、轨迹、落点与状态标记使用纯色几何图形，不依赖美术资源。

## 7. 后续模块（方向已锁定，当前阶段暂不实现）

以下来自完整需求，方向明确但不在当前阶段范围内：

- **账号 / 用户体系**：注册登录、用户信息（名称、头像、uid）。
- **个人数据**：历史记录列表与查看、编辑（含在路线上拖动调整鸟种落点）、删除；收藏的线路（外部导入的记录、自己的历史线路）。
- **分享与导入**：以链接或图片分享到社交媒体；他人可复制链接导入保存。
- **导入观鸟记录中心**：一键将记录导入观鸟记录中心（定点记）。
- **设置**：清空缓存、版本信息等。
- **鸟种模糊匹配**：无法确认鸟种时按特征匹配，本条不记具体种名，并引导用户前往 Merlin 进一步识别。
- **国内瓦片源接入**：保证国内稳定访问，含坐标系纠偏。

> 后续模块中尚未收敛的选型与细节（如国内瓦片源的具体选择、模糊匹配的特征维度、分享的具体形态）记录在 `docs/exploration.md`，确认落地前不写入本文档。
