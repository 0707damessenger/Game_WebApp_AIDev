# 旅行采集与宝箱实施计划

## 目标

在单一桌面餐车悬浮窗中实现旅行自动采集、有限宝箱收纳与可随时开启的宝箱入口，不扩展到经济、研发或新闻系统。

## 实施顺序

1. 在唯一 `CONFIG` 中定义旅行推进节奏、地区食材池、宝箱容量和简化奖励。
2. 为旅行库存状态写单元测试，覆盖活动条件、地区差异、宝箱入库、满仓错过与开箱奖励。
3. 实现独立旅行状态模块，避免把资源产出混入番茄钟阶段状态机。
4. 在应用层仅于旅行计划活动中推进采集，并在同一份公开状态中保留库存与宝箱。
5. 在悬浮窗口内增加紧凑的食材、宝箱可视状态和可点击开箱入口；工作期保持开箱可用，安排和番茄钟入口继续锁定。
6. 补充浏览器交互测试，并完成宽屏、窄屏和自动化浏览器检查。

## 验收标准

- 旅行、地区、库存和宝箱状态能从界面和公开状态中一致确认。
- 宝箱满仓后没有隐性排队或补发；开箱后新遇到的宝箱才可再次收入。
- 工作期间开箱不解除管理锁定。
- 所有测试通过，浏览器没有控制台错误，悬浮窗在窄屏内不产生横向溢出。
