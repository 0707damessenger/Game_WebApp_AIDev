# 桌面餐车 - 设计讨论记录

> 本文档记录“定方向、理情况、想方案、明作法、做总结”的讨论过程。正式设计结论以 [design.md](../design.md) 为准。

## 1. 目标

在本轮设计讨论中，确认游戏的核心体验、长期系统关系与首个可验证原型范围；结合指定参考游戏评估风险和扩展方向，最终分别形成正式设计文档、参考游戏分析和未确认方案文档，暂不开发原型。

### 成功标准

- 长期完整设计与首个原型范围明确分层。
- 经营、旅行、研发、新闻、成长与番茄钟能够解释为一条连贯循环。
- 对低干扰、系统聚焦和错过焦虑给出有参考依据的判断。
- 未确认方案不进入正式设计契约。

## 2. 当前情况

### 已确认事实

- 新项目从零开始，没有可继承原型、测试数据或玩家反馈。
- 正式版本目标为 Windows 与 Steam，首轮先做网页原型。
- 工作时可在置顶小窗和普通窗口之间切换。
- 番茄钟关闭时，经营与旅行需要玩家主动启动。
- 离线收益延续退出前模式，存在累计上限并受新闻影响。
- 经营使用预先烹饪的库存，顾客可在首选售罄后选择替代餐品。
- 旅行按地区自动巡游；宝箱满仓后停止收集，但工作阶段仍可主动开箱。
- 成长以线性升级为基础，新闻提供主要的阶段规划变化。
- 全局独立键盘按下和鼠标点击直接累计吆喝值；长按自动连发不重复计数。
- 首个原型需要最小化打通番茄钟、旅行、备餐、经营和新闻。

### 主要问题

- 游戏奖励可能诱导玩家在工作阶段分心。
- 模块数量较多，核心循环可能被功能堆叠稀释。
- 现实时间新闻和离线结算可能制造错过焦虑。

### 外部条件缺口

- 没有玩家测试可以证明小窗是否足够舒适、收益差距是否足够低。
- 没有实测数据可以确定离线收益、吆喝衰减、新闻持续时间和宝箱容量。
- 美术制作方式与长期动画产能尚未验证。

### 方法缺口

- 如何让全局输入奖励正常工作，而不是奖励刷输入。
- 如何让现实时间新闻产生规划价值，同时允许玩家安心错过。
- 如何用少量视觉内容支撑长期可见成长。

## 4. 情况确认结论

当前没有零参考风险。桌面陪伴、餐饮资源链、增量展开和生产力工具均有高匹配度案例；真正缺失的是把这些基底组合到同一产品后的体验数据，因此首个原型必须围绕组合后的注意力与循环连贯性验证。

## 5. 候选方案

### 方案 A：专注优先的双层循环

**核心逻辑**：工作阶段只展示自动经营或旅行的可观看过程；休息阶段用一次短规划完成“看新闻、处理收获、备餐、选模式与地点”。

- 游戏参考：《Spirit City: Lofi Sessions》的生产力工具与舒适奖励、《Rusty's Retirement》的贴边低干扰、《繁荣美食市场物语》的采购与放置销售。
- 相似之处：都把后台推进与短时主动管理分开。
- 差异边界：本项目额外加入经营与旅行二选一、全局输入吆喝及新闻规划，必须限制这些机制争夺注意力。
- 方法论依据：体验设计要求所有机制服务“舒适陪伴”；优雅性要求新闻同时连接地区、食材、菜单和顾客。
- 与目标的契合：最直接验证番茄钟、小窗陪伴和资源循环能否共存。
- 核心取舍：牺牲工作阶段的操作深度，避免即时事件成为主要乐趣来源。
- 性价比：必摘的果子。

> 📎 [Spirit City: Lofi Sessions](https://store.steampowered.com/app/2113850/) - 🟢 - 生产力工具可以通过装扮与陪伴奖励形成长期动力。
>
> 📎 [Rusty's Retirement](https://store.steampowered.com/app/2666510/) - 🟢 - 贴边运行、缩放和低干扰模式已经过较大玩家样本验证。

### 方案 B：观赏优先的旅行明信片

**核心逻辑**：把每次经营或旅行视为一段动态明信片，长期目标是看到餐车、地区、熟客和沿途生活逐渐丰富，经济效率只用于打开更多画面变化。

- 游戏参考：《观鸟笔记》的桌面明信片、地点装饰、访客与行为解锁，以及《Rusty's Retirement》的可见自动化。
- 相似之处：第一价值都是“不操作时也值得观看”。
- 差异边界：本项目拥有更长的食材与销售资源链，若全部轻量化，新闻和经营规划可能缺乏意义。
- 方法论依据：体验设计强调感官与变化是低门槛情感触发器；可见升级能让重复挂机产生新鲜感。
- 与目标的契合：最能保证美观、和谐与陪伴感，并强化用户选择的长期动力 A。
- 核心取舍：弱化效率优化，且对场景、角色动作和动画内容产能要求最高。
- 性价比：必要的攻坚。

> 📎 [观鸟笔记](https://store.steampowered.com/app/4111370/) - 🟢 - 动态明信片、地点与访客内容已经验证观赏型桌面陪伴的吸引力。

### 方案 C：经营优先的增量餐车

**核心逻辑**：以产能和利润增长为主目标，逐步解锁地区、供应链、菜单、自动化与市场新闻，让玩家持续优化经营效率。

- 游戏参考：《繁荣美食市场物语》的餐饮资源链、《Universal Paperclips》的阶段展开、《TBH: Task Bar Hero》的自动成长与构筑。
- 相似之处：都用自动产出、瓶颈和升级推动持续增长。
- 差异边界：本项目承担真实专注工具职责，不能采用高频点击、密集掉落或持续换装检查作为主要节奏。
- 方法论依据：渐进展开可以降低早期学习成本；平衡性原则要求新闻制造情境选择，而不是出现固定最优路线。
- 与目标的契合：最能满足用户选择的长期动力 C，并为新闻规划提供较大空间。
- 核心取舍：最容易偏离平缓陪伴，系统和数值成本最高，也最可能让工作阶段变成收益监控。
- 性价比：完成核心体验验证后再看。

>

### 推荐

推荐方案 A。它先保护本项目最难替代的差异点“番茄钟期间的桌面陪伴”，同时保留 B 的可见成长作为表现原则、保留 C 的新闻效率规划作为休息阶段深度；这样不是删除另外两条动力，而是明确它们服务于专注节奏。

## 6. 决策结论

- 采用方案 A“专注优先的双层循环”作为主结构。
- 吸收方案 B 的可见成长：餐车改装、熟客、地点和经营成果应改变可观看画面。
- 吸收方案 C 的新闻规划：新闻改变短期路线和菜单价值，但不引入高频收益监控。
- 不采用“观赏内容独立于经济循环”的完整方案 B，避免经营与观赏割裂。
- 不采用“经营效率压倒专注体验”的完整方案 C，避免工作阶段变成库存和收益检查。

该结论已经同步写入 [design.md](../design.md) 的总体结构章节。

## 7. 行动计划与总结

### 首个开发模块

选择“番茄钟节奏骨架”作为首个独立增量。该模块先验证工作/休息切换、阶段安排、小窗/普通窗口职责和工作阶段管理限制；资源结果使用简化反馈，不提前实现完整经济循环。

### 追踪方式

- 完成一次从阶段安排到工作、再到休息的完整状态循环。
- 检查经营、旅行和地区选择能否正确带入工作阶段。
- 检查工作阶段的管理功能是否不可用，休息阶段是否恢复。
- 网页原型使用短计时，便于一次测试中覆盖完整状态循环；正式番茄钟时长不在本模块锁定。
- 只验收规则和状态是否正确，不把画面陪伴感或低干扰手感列为本模块通过条件。
- 后续需要为低干扰体验安排独立的可交互测试增量。

### 应变预案

- 首个网页模块使用界面状态模拟小窗与普通窗口。
- 网页无法证明系统级始终置顶、透明窗口和全局键鼠统计是否可靠，这些能力不作为首个模块的失败条件。
- 首个模块通过后，再建立独立的桌面能力验证模块；若桌面能力验证失败，仍可保留普通窗口产品形态，不推翻番茄钟状态规则。

### 总结与后续

- 已决定：采用专注优先的双层循环，观赏成长与新闻规划服从低干扰目标。
- 已放弃：不采用观赏或经营效率单独主导全局的结构，也不在首个模块内同时验证桌面系统能力。
- 下一步：为“番茄钟节奏骨架”编写独立实施计划，之后按工作区增量原则开发并验证该模块。
- 首个模块通过标准：计时、阶段切换、模式与地区带入、工作阶段管理限制均符合正式设计。
- 后续独立验证：小窗陪伴感、低干扰手感、真实桌面窗口能力、全局输入统计与隐私信任。
