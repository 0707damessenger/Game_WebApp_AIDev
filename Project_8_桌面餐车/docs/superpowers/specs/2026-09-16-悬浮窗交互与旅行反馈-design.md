# 悬浮窗交互与旅行反馈设计

## 目标

让桌面餐车更符合桌面悬浮伴侣的操作直觉，并让旅行资源从“数字直接增加”变为“道路出现—靠近餐车—收集反馈—库存更新”的可观看过程。

## 窗口与菜单

- 餐车主体包含标题栏、场景、收获栏与状态栏，这些非控件区域可拖动整个悬浮窗。
- 菜单不作为拖动区域；在菜单上拖动不会改变悬浮窗位置。
- 按钮、开关和宝箱等控件优先响应点击，不触发拖动。
- 菜单在餐车主体上方向上展开，不改变主体在桌面上的位置，并随主体一起移动。
- 开始专注或手动活动后，菜单自动收起。

## 番茄钟与节奏

- 番茄钟改为标题栏中的小开关，不占用独立菜单页签。
- 工作阶段开关锁定；关闭番茄钟时保留手动活动流程。
- 休息阶段允许先安排下一段，再点击开始专注直接进入新工作阶段。

## 旅行反馈

- 食材和宝箱使用同一套道路物件生命周期：出现、接近、收集、结算。
- 库存只在收集反馈完成后变化，确保画面反馈先于数值反馈。
- 宝箱满仓时，道路宝箱仍完成经过过程，但不会进入槽位，也不弹出催促提示。
- 网页原型继续使用纯色几何图形，不引入正式美术资源。

## 阶段气泡

- 每个阶段变化事件只触发一次进入动画和一次自动消失计时。
- 同一事件持续显示期间，普通计时刷新不得重新播放进入动画。

## 验证

- 自动测试覆盖休息阶段提前开始、菜单结构、自动收起、道路物件延迟结算和阶段气泡不重复进入。
- 浏览器验证覆盖主体拖动、菜单不可拖动、菜单向上展开、旅行收集动画、开箱与窄屏布局。
