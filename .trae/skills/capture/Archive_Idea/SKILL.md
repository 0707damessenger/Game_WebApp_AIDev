# Archive_Idea 技能说明

## 何时使用：
当用户在一个设计方向上进行了尝试或讨论，但最终决定**明确不采用**这个方向时，使用此技能。

> **与 Record_Idea 的区别**：`Record_Idea` 用于「值得保留，也许以后会用」；`Archive_Idea` 用于「明确否决，记录教训」。

## 操作步骤：
1. **生成归档文档**：在 `docs/archives/` 目录下创建一个新的 Markdown 文件。
   - 文件命名格式：`idea_[关键词]_rejected.md`（例：`idea_combat_action_points_rejected.md`）
   - 归档记录属于 `docs/` 下的补充子文档，不得替代 `docs/design.md`
2. **文档结构**：
   - **标题**：想法的名称
   - **提出背景**：当时是为了解决什么问题或处于什么讨论背景下提出的该想法
   - **内容概述**：这个被搁置的想法具体是什么（包含尝试过的机制、数值设定、相关草案等）
   - **被否决的原因**：详细记录为什么这个想法没有被采纳（例如：系统太复杂、与某项核心支柱冲突、当前的实现成本过高等）
   - **未来参考价值**：在什么特定情况或前提条件改变下，这个想法可能会被重新翻出来参考
3. **主契约关系**：如果该归档记录影响了当前设计边界、禁用方案或取舍结论，应同步更新 `docs/design.md`，补充引用关系与结论摘要。
4. **输出要求**：整个归档文档**必须使用简体中文**编写。

## 完成自检

- [ ] 归档文件已创建于 `docs/archives/idea_[关键词]_rejected.md`
- [ ] 文档包含五个章节：标题 / 提出背景 / 内容概述 / 被否决的原因 / 未来参考价值
- [ ] 否决原因具体明确，不是「不好」之类的空话
- [ ] 文档使用简体中文
- [ ] 若归档结论影响正式设计边界，已同步回写 `docs/design.md` 并补充引用关系
