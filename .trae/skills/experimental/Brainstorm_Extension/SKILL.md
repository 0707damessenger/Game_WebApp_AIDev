# Brainstorm_Extension 技能说明

## 何时使用：
当用户希望在现有设计框架的基础上进行创意扩展时，例如：
- 用户说"帮我发散一下"、"有什么可以延展的"、"基于这个扩展一些想法"
- 用户希望探索某个系统的更多可能性，但还没有明确方向
- 讨论陷入瓶颈，需要新思路突破

## 操作步骤：
1. **建立发散基础**：读取 `docs/design.md` 中与当前话题相关的正式设计约定，并检查 `docs/archives/` 中相关的被搁置想法。确保发散方向不是重复提出已被否决的方案。
   > **⚠️ 防护检查**：如果 `docs/design.md` 中尚未明确当前讨论主题的目标、限制或核心规则，应先补全主契约，再进行创意发散。
2. **创意发散**：围绕当前系统/机制，从以下维度进行延展探索（根据情况选择相关维度）：
   - **深度延展**：将现有机制推向极端，它会有什么有趣的极端状态？
   - **横向联动**：如果这个机制与游戏中其他系统产生联动，会产生什么化学反应？
   - **玩家视角**：玩家在这个机制下，会诞生哪些意外的、有趣的行为策略？
   - **反向思考**：如果把这个机制的逻辑颠倒或取反，会产生什么？
   - **类比借鉴**：同类游戏（如 Slay the Spire、Balatro、Dicey Dungeons 等）是如何处理类似问题的？有哪些可以借鉴的模式？
3. **输出创意清单**：将发散出的想法以简洁的列表形式呈现给用户。每条想法附一句话说明其核心趣味点或潜在风险。
4. **记录有价值的想法**：将本次发散中用户认为有价值但暂不深入的想法，调用 `Record_Idea` 技能存入 `docs/ideas/`。
5. **主契约回写规则**：如果本次发散形成了新的正式设计方向、筛选原则或方案结论，必须同步更新 `docs/design.md`，并补充相关想法文档的引用关系与结论摘要。
6. **输出要求**：所有输出**必须使用简体中文**。

## 完成自检

- [ ] 已读取 `docs/design.md` 中与当前话题相关的正式设计约定（若信息不足则先补主契约）
- [ ] 已检查 `docs/archives/` 中相关被搁置想法，避免重提已否决方案
- [ ] 创意清单每条均附核心趣味点或潜在风险（不只是列提案）
- [ ] 用户认为有价值但暂不深入的想法已调用 `Record_Idea` 记录
- [ ] 若已形成正式设计结论，已同步回写 `docs/design.md` 并补充引用关系
