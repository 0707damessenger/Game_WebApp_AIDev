# Game_Design_Principles

本技能汇集了从经典游戏设计书籍中提炼的核心设计原则。AI 在进行设计评审、创意发散或质量提升时应参考这些原则。

## 何时使用

- **设计评审**：评估一个设计方案是否遵循了良好的设计原则
- **创意指导**：在头脑风暴或方案设计时，引用原则作为思考框架
- **质量提升**：识别设计中可能存在的问题，并给出基于原则的改进建议
- **设计讨论**：为设计决策提供理论支撑和参考案例

## 原则索引

| 原则 | 一句话摘要 | 文件 |
|------|-----------|------|
| 体验设计 | 游戏的本质是体验引擎——通过机制触发情感，而非提供内容 | [experience_design.md](knowledge/experience_design.md) |
| 优雅性 | 优雅 = 用最小的设计成本创造最大的体验多样性 | [elegance.md](knowledge/elegance.md) |
| 平衡性 | 平衡的核心目的是公平与深度，而非所有选项等价 | [balance.md](knowledge/balance.md) |

## 引用规范

在设计讨论中引用原则时，使用以下格式：

> 根据**体验设计**原则（《体验引擎》）：[具体引用]

## 操作步骤

1. 根据当前设计任务，判断哪些原则相关
2. 阅读对应的知识文件，重点关注"设计指导"部分的 Do/Don't/Ask
3. 将原则应用到具体设计方案中，给出基于原则的分析和建议
4. 如有需要，引用知识文件中的案例来说明观点
5. 若原则分析被用于正式设计判断或方案取舍，必须同步更新 `docs/design.md`，并补充相关子文档或依据来源的引用关系与结论摘要

## 主契约关系

- 原则文件属于评估与分析依据，不得替代 `docs/design.md`
- 原则本身不直接构成项目设计结论
- 只有当原则被用于正式设计判断、方案取舍或规则约定时，才需要回写 `docs/design.md`
